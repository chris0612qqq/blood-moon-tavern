## 1. 目標與範圍

出遊時面對面玩狼人殺，用手機取代主持人。一個常駐的遊戲房間（**單一房間**，房內總人數上限 20），可以中午玩兩輪、晚上續玩。網頁版 PWA，iOS 用 Safari「加入主畫面」，不需 Apple 開發者帳號（0 元）。

## 2. 已確認決策

| 項目 | 決定 |
|---|---|
| 形式 | 網頁版（PWA），0 元 |
| 伺服器 | 放你家的電腦（要開機、不睡眠、有網路）；HTTPS 用免費 Cloudflare Tunnel |
| 管理員 | 房主，**自己也玩**，只負責操作進度；不能偷看他人角色（緊急查看見 §7，待確認） |
| 房間 | 常駐；狀態與聊天存資料庫；玩家重進從名單選回名字＋PIN |
| 進房 | 房間密碼＋名字＋大頭貼（拍照／選相簿，可拖曳縮放裁成圓形）＋PIN |
| 發牌時機 | 進房時**沒有角色**；管理員按「開始」才以當下人數隨機發牌；發牌後人數鎖定，遲到者只能旁觀聊天室，下一局才加入 |
| 角色 | 狼人、村民、預言家、女巫、獵人（守衛、白痴先不加） |
| 旁白 | 傳統式（念「狼人請睜眼」…），由一支「主機」手機念，其他手機同步顯示字幕 |
| 夜間操作 | 有行動的角色在自己螢幕點選目標，**全部確認後才進下一步** |
| 狼人選刀 | 選人時所有狼人即時看到彼此選了誰；全部選同一人才確認 |
| 警長 | 不用；白天按座位輪流發言 |
| 死亡玩家 | 公共頻道不能發言（可看）；狼人仍可在狼人頻道發言；角色欄位標示「死亡」；看不到他人角色 |
| 聊天 | 文字、照片、語音訊息皆可；顯示發言者與內容；日夜都開放、暫停時照常 |
| 狼人頻道 | 狼人專用；狼人在公共頻道可選「自己名字」或「狼人」標籤發言（文字／照片／語音皆可）；真實發言者遊戲中保密，結束後「看真相」公開 |
| 角色卡 | 角色、能力說明、武俠風故事、插圖 |
| UI 風格 | 龍與地下城風（暗色奇幻、羊皮紙、金屬邊框、二十面骰），不使用官方商標與素材 |

## 3. 規則

### 3.1 配角色表（依按下「開始」時的人數；神職固定預言家、女巫、獵人，6 人局無獵人）

|---|---|---|---|---|---|---|
| 6 | 2 | 2 | | 14 | 5 | 6 |
| 7 | 2 | 2 | | 15 | 5 | 7 |
| 8 | 2 | 3 | | 16 | 5 | 8 |
| 9 | 3 | 3 | | 17 | 6 | 8 |
| 10 | 3 | 4 | | 18 | 6 | 9 |
| 11 | 4 | 4 | | 19 | 6 | 10 |
| 12 | 4 | 5 | | 20 | 7 | 10 |
| 13 | 4 | 6 | | | | |

（7 人以上：狼人＋預言家＋女巫＋獵人＋村民 = 總人數；6 人：2 狼＋預言家＋女巫＋2 村民。）

### 3.2 角色能力

| 角色 | 陣營 | 能力 |
|---|---|---|
| 狼人 | 暗夜 | 每晚與同伴共同選擇一人擊殺；狼人頻道密談；公共頻道可用「狼人」標籤發言 |
| 村民 | 好人 | 無技能；白天發言、投票 |
| 預言家 | 好人 | 每晚查驗一人是狼人或好人 |
| 女巫 | 好人 | 解藥、毒藥各一瓶、各限用一次，同夜不可雙用；解藥僅首夜可自救【暫定】 |
| 獵人 | 好人 | 死亡時（**被毒死除外**）可立刻帶走一人。**開槍時身分自然公開**（旁白會說「獵人帶走了○○」） |

### 3.3 夜晚結算
死亡名單 = 狼人目標（未被解藥救）＋毒藥目標。空刀＝無狼人目標。

### 3.4 白天
- 發言：依座位順序輪流，只輪存活者，預設每人 60 秒【暫定】。起點：昨夜死者的下一位，平安夜從座位 1【暫定】。
- 投票：存活者同時秘密投票（可棄票，不可投自己），同時揭曉。最高票者放逐；**平票沒人出局**。
- 出局者**不公開角色**（獵人開槍除外），只標示「死亡」。

### 3.5 勝負（屠城）【暫定】
判定時機：天亮公布死亡後、獵人開槍後、投票放逐後。
- 存活狼人 = 0 → 好人勝
- 存活狼人 ≥ 存活好人 → 狼人勝

### 3.6 特殊情況
- 狼人選刀倒數結束仍不一致：從最高票者中隨機（全部平票則隨機一人；沒人選則空刀）。
- 已死亡的角色回合：旁白照念，隨機等 10–20 秒再繼續，避免從節奏判斷誰死了。獵人夜間無行動，不念旁白。
- 倒數預設：夜晚各步 60 秒、發言 60 秒、投票 60 秒【暫定】，皆為可調常數。時間到：預言家／女巫＝不行動，投票＝棄票，狼人＝依上一條。
- 開始後被踢的玩家：視為死亡，不公開角色，照常判定勝負。

## 5. 遊戲流程與手機畫面

### 5.0 共通畫面骨架
底部五個分頁：**遊戲**（骰子圖示）｜**聊天**（羽毛筆）｜**狼人頻道**（爪，僅狼人）｜**我的角色**（盾牌，角色卡需**長按**才顯示）｜**玩家**（座位、存活／死亡／離線；不顯示他人角色）。
管理員頂端多一條控制列：目前階段＋**暫停／繼續**＋**強制下一步**＋「⋯」（更多功能，見 §7）。

### 5.1 大廳（酒館）
- 玩家：開網址 → 房間密碼 → 名字、拍照裁切大頭貼、設 4 位數 PIN → 進入大廳。重進者按「我回來了」→ 從名單選名字＋PIN。
- 畫面：房名、人數 `N/20`、圍坐頭像、聊天室。
- 管理員：拖曳調整**座位順序**（請依實際圍坐排好）、長按頭像踢人、「開始」按鈕（< 6 人停用，顯示「還需 X 人」）。

### 5.2 開始與發牌
1. 管理員按「開始」→ 確認視窗「目前 N 人，配：X 狼、預言家、女巫、（獵人）、Y 村民」。
2. 確認後人數鎖定，伺服器洗牌（`secrets` 亂數）。
3. 畫面：全螢幕暗幕，二十面骰滾動 → 卡背（金色紋章）。**長按卡背**翻面看角色卡，放開蓋回。狼人另顯示同伴名字並解鎖狼人頻道。
4. 每人按「我看過了」，全員（或管理員強制）→ 第 1 夜。

### 5.3 夜晚（每晚重複）
通則：旁白由主機念出 → 該角色螢幕出現操作 → 按「確認」→ 全部確認後下一步。選人可改，按確認才送出。每步 60 秒倒數。

| 步驟 | 旁白 | 該角色的畫面 | 其他人的畫面 |
|---|---|---|---|
| 天黑 | 「天黑請閉眼」 | — | 夜空、月亮、霧；旁白字幕；進度圖示（狼人→預言家→女巫） |
| 狼人 | 「狼人請睜眼，請選擇今晚要殺的人」 | 存活者頭像格＋「空刀」。每位狼人的選擇即時顯示爪痕標記＋同伴縮寫。全選同一人自動確認 | 同上 |
| 預言家 | 「預言家請睜眼…」 | 存活者（不含自己）→ 確認 → 水晶球動畫，顯示「○○：狼人／好人」→「我知道了」 | 同上 |
| 女巫 | 「女巫請睜眼」 | 兩瓶藥（已用的灰掉）。①顯示被殺者→「救他／不救」；②若毒藥還在且本晚未用解藥→「用毒藥（選人）／不用」→ 確認 | 同上 |
| 天亮 | 「天亮請睜眼」 | — | 轉黃昏色；公布結果 |

狼人畫面側邊有可摺疊的狼人頻道視窗，方便討論。

### 5.4 天亮
- 公布「平安夜」或「昨晚死亡的是：○○、□□」，死者頭像依序灰階化，標示「死亡」。
- 死者手機進入死亡狀態（見 §3、§6）。
- **勝負檢查 #1**；若死者是獵人（非被毒）→ 該手機跳出「請選一人帶走」→ 再次勝負檢查。

### 5.5 白天發言
- 畫面：目前發言者大頭像＋倒數環；座位順序條（輪過的變暗）。
- 輪到的人：手機震動＋「該你發言」＋「結束發言」；其餘人看「○○ 發言中」。管理員多一個「跳過」。
- 這段是面對面講話；聊天室同時開放。

### 5.6 投票與放逐
- 「投下你的一票」：存活者頭像格（不含自己）＋「棄票」＋確認；確認後顯示「等待其他人…」與已投人數（不顯示是誰）。
- 揭曉：逐一翻開票、頭像間畫出箭頭、最高票者放大；文字「○○ 被放逐」或「平票，無人出局」。
- 出局者標示死亡；若是獵人 → 開槍 → **勝負檢查 #2** → 無勝負回到夜晚。

### 5.7 暫停與繼續
- 「暫停」：全員顯示「遊戲暫停中」、倒數凍結、**聊天照常**；「繼續」從原步驟與剩餘秒數接續。夜晚也能暫停（旁白停止，繼續後重念當前步驟）。
- 白天常用：暫停去吃飯閒聊，晚上回來按繼續。

### 5.8 結束
- 旁白「遊戲結束，○○ 獲勝」；勝利畫面（好人＝金色日出，狼人＝紅月）。
- 公布全部角色（頭像＋名字＋角色卡縮圖）。
- **看真相**：狼人頻道完整紀錄＋公共聊天中每則「狼人」標籤訊息的真實發言者。
- 管理員選項：**再玩一局**（同批人重發牌）｜回大廳｜結束遊戲。結束後聊天室與紀錄保留。
- 管理員中途「結束遊戲」：二次確認，直接進入公布角色，不計勝負。

### 5.9 設定頁
旁白（我是主機／不是主機、音量、測試發聲）｜音效開關｜保持螢幕亮著｜減少動畫（跟隨系統）。

## 6. 聊天

| 情境 | 公共頻道 | 狼人頻道 |
|---|---|---|
| 大廳、結束後 | 所有人可發言 | — |
| 遊戲中，活著的好人 | 用自己名字發言 | 看不到 |
| 遊戲中，活著的狼人 | 可選「自己名字」或「狼人」標籤 | 可發言 |
| 遊戲中，死亡的好人 | 只能看 | 看不到 |
| 遊戲中，死亡的狼人 | 只能看 | 可發言 |
| 暫停中、夜晚 | 照常 | 照常 |

- 內容：文字（≤500 字）、照片（上傳前自動去除拍攝時間／地點並壓縮）、語音（按住錄音、上滑取消，≤60 秒）。
- 不可編輯、撤回；**無**「正在輸入」、已讀、最後上線時間（避免洩漏誰是狼人）；玩家名單只顯示「離線」標記。
- 狼人切換「發言身分」：輸入框上方切換「我自己／狼人」；切到「狼人」時輸入框變暗紅＋爪痕，避免誤發；自己的畫面在該則旁標「（你以狼人身分發言）」。
- 保留期限：訊息與媒體皆保留 7 天【暫定】。
- 限制：面對面玩，旁人看得到你在不在打字、聽得出語音是誰，App 管不了；語音發言會洩漏聲音，這是你選擇的取捨。

## 7. 管理員功能與當機對策

**功能**

| 功能 | 說明 |
|---|---|
| 開始／暫停／繼續／結束 | 開始前顯示人數與配角色確認 |
| 強制下一步 | 跳過卡住的玩家（未投票＝棄票，未行動＝不行動） |
| 回上一步 | 讀取上一個快照（每步保留，最近 20 份） |
| 重發角色卡 | 只重顯示該玩家自己的角色，不換牌 |
| 指定旁白主機 | 預設管理員手機，可換別人的 |
| 手動修正狀態 | 改存活／死亡；寫入紀錄並在公共聊天通知 |
| 重置本局 | 保留房間與人員，重新發牌 |
| 踢人 | 移出並封鎖該裝置；可再換新房間密碼 |
| 調整座位 | 僅大廳 |
| 緊急查看全部角色 | 二次確認；公共聊天自動發出「管理員使用了緊急查看」【待確認是否保留】 |
| 換裝置接手 | 另一支手機用管理員的名字＋PIN 登入即接手（後登入擠掉前一台） |

管理員死亡後仍保有控制列【暫定】。

**當機對策**

| 狀況 | 處理 |
|---|---|
| 伺服器程式當掉 | 啟動腳本自動重啟；狀態每步寫入資料庫，重啟後自動進入**暫停**，管理員按「繼續」 |
| 電腦睡眠／斷網／斷電 | 伺服器執行時以 Windows API 阻止睡眠（仍建議電源選項設插電不睡眠）；斷電斷網只能等電腦回來，資料在硬碟不丟 |
| 管理員手機斷線 | 離線超過 **30 秒寬限**【新增，暫定】才自動暫停（iOS 切 App／鎖屏會瞬間斷線，不應一斷就暫停）；回來按「繼續」 |
| 旁白主機手機休眠 | 旁白停止並提示，可指定其他手機當主機 |
| 玩家手機當機 | 倒數到自動跳過，或管理員強制下一步；玩家重開 App 以名字＋PIN 回原位與狀態 |
| 玩家同時用兩台手機 | 後登入的擠掉前一台 |
| 備份 | 資料庫每 10 分鐘自動備份一份到 `data/backup/`（保留最近 10 份），每次暫停也備份；電腦故障時把備份放到另一台電腦即可接續（出發前請把備份放到手機或雲端） |

## 8. UI 設計

### 8.1 方向
暗色奇幻——酒館、地下城、羊皮紙卷軸、金屬邊框、燭光、二十面骰；文字走武俠風。**只借風格**：「Dungeons & Dragons」名稱、標誌、字型、官方插圖一律不用，圖形（骰子、盾牌、卷軸、爪痕、紋章）由我以 SVG 自繪。三原則：夜晚畫面要暗不刺眼；該做的事一眼看懂（大按鈕、大頭像、一個主要動作）；狀態一律「圖示＋文字＋顏色」（色盲友善）。

### 8.2 設計變數

| 變數 | 色碼 | 用途 |
|---|---|---|
| bg-night | `#14100d` | 主背景 |
| bg-stone | `#1f1a15` | 面板（石板） |
| parchment / parchment-dark | `#e8d9b5` / `#cdb98a` | 羊皮紙（聊天、角色卡故事區） |
| ink | `#2b1d12` | 羊皮紙上的字 |
| gold / gold-bright | `#c9a24a` / `#e8c872` | 邊框、主要按鈕、選中發光 |
| blood | `#8e1b1b` | 狼人／危險／死亡 |
| ember | `#d9702b` | 火光、倒數緊迫 |
| moss | `#4a6b3a` | 好人／存活 |
| arcane | `#5b4b8a` | 預言家 |

### 9.5 狀態機
```
LOBBY → DEAL → ACK(全員「我看過了」) → NIGHT[wolf → seer → witch] → DAWN → (HUNTER_SHOT) → CHECK_WIN
      → DAY_SPEAK(逐人) → VOTE → REVEAL → (HUNTER_SHOT) → CHECK_WIN → NIGHT …
      → END（公布角色、看真相）→ LOBBY／再玩一局
```
`phase`、`step`、`deadline_ts` 每次變化先寫資料庫再廣播；暫停記 `paused_remaining_s`；伺服器重啟時若有進行中的遊戲自動設為暫停；計時由伺服器負責，客戶端用伺服器時間校正。

### 9.6 規則引擎（`rules.py`，純函式、不碰網路與資料庫）
`role_counts(n)`｜`deal(players)`｜`resolve_night(state)`｜`tally_votes(votes)`｜`check_win(state)`｜`next_speaker(state)`｜`wolf_consensus(picks, alive_wolves)`。

### 9.7 通訊協定（JSON over WebSocket；媒體上傳走 HTTP `POST /api/media`）
- 客戶端→伺服器：`join`／`rejoin`｜`deal.ack`｜`chat.send`｜`night.select`｜`night.confirm`｜`witch.act`｜`hunter.shoot`｜`speak.end`｜`vote.cast`｜`vote.confirm`｜`admin.*`。
- 伺服器→客戶端：`state`（該玩家可見的完整狀態，連線／重連時送）｜`phase`｜`wolf.picks`（只送狼人）｜`result.seer`／`result.witch`（本人專屬）｜`chat.msg`（已過濾真實發言者）｜`roster`｜`end`｜`error`。

### 9.8 安全
- 房間密碼＋玩家 PIN（scrypt 雜湊）；登入後發 session token（HttpOnly cookie）。
- 房內總人數上限 20，第 21 人顯示「房間已滿」；WebSocket 檢查 Origin；每人訊息速率限制（每秒 3 則）。
- 文字長度 ≤ 500、前端一律 `textContent` 顯示；上傳：照片 ≤ 5 MB、語音 ≤ 60 秒且 ≤ 2 MB，檢查檔頭實際格式，檔名由伺服器產生。

### 9.9 測試計畫
1. 規則單元測試：6–20 人配比、夜晚結算組合（救毒同夜、自救、獵人被毒、平安夜）、平票、勝負。
2. 整局機器人模擬（6–20 人，隨機行動）：斷言機器人**從未收到**他人角色、非狼人收不到狼人頻道與「狼人」訊息的真實發言者；暫停／繼續與伺服器重啟可接續。
3. 多分頁手動驗證：我開多個瀏覽器分頁完整操作一局，交付前先自行跑過。
4. iOS 實機（你協助）：加入主畫面、旁白發聲、錄音、拍照、長按看角色卡、鎖屏後重連。

### 9.10 開發里程碑
M1 規則引擎＋單元測試 → M2 伺服器＋狀態機＋機器人整局模擬 → M3 前端：登入、大廳、角色卡、聊天 → M4 前端：夜晚、白天、投票、結算 → M5 照片、語音、旁白、PWA → M6 管理員應急工具、備份、啟動腳本 → M7 套用 UI 美術。

## 10. 限制與風險（請知悉）

1. **免費 Tunnel 網址每次重開都會變**。後果比只是「重傳網址」嚴重：session cookie 與 PWA 的「主畫面圖示」都綁網址，網址一變，大家要重新開新網址、重新「加入主畫面」、用名字＋PIN 回原位。對策：旅途中盡量不要重啟電腦或程式；想要固定網址需買網域（約每年 10 美元）改用具名 Tunnel。
2. 電腦整台掛掉且沒有備用電腦，當天無法玩。
3. iOS 鎖屏後旁白、語音會停止，需保持螢幕亮著（Wake Lock 無效時要手動）；主機與管理員手機尤其重要。
4. **你本人能直接讀取電腦上的資料庫檔案**（含角色與「狼人」發言者），技術上無法阻止，只能靠自律；App 本身對管理員已做保密。
5. 面對面的洩漏（誰在打字、誰的聲音）App 管不了。
6. 語音發言會洩漏聲音（你已選擇接受）。
